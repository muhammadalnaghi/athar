# WM028-P — Guarded result-renderer integration

## Goal and surface

Mode: Operate. Integrate the delivered read-only Debt and Cash-path result bodies into the existing Plan feature, preserving Athar’s typography, spacing, palette, exact money formatter, resource-reactive locale, three bottom destinations and Plan001 semantics. This is an implementation slice of WM028-P-debt-forecast-result-views, not full WM10/16 acceptance. Existing goal and investment functionality remains untouched.

## Ownership and implementation

The parent owns integration and the only Gradle/device slot. Freeze the current accepted 571 source bindings, the renderer source bodies, destination absence, resource declarations and prior test identities before changing code. Worker hash literals must independently pass the exact 64-hex format check before comparison; an invalid literal is retained as invalid evidence, never repaired. Independently hash the actual source bytes for any replacement binding.

Split the oversized delivered Kotlin files by entry rendering, money/path views, disclosures and synthetic previews. Preserve mandatory callbacks without no-op production defaults. Fix source-proven compilation gaps, including the missing Composable preview import. Pure presentation policy helpers may defensively withhold strategy ranking for unsettled or unlike-currency results and cash headlines outside CONFIDENT. They do not change calculator arithmetic.

Use vertical label/value stacks where a long Arabic label or date would otherwise compete horizontally with exact money. Currency partitions remain literal and separate; unavailable available/reserved cash is unknown, not zero. Partial debt totals are not final costs. Dates appear only for actually settled strategies, including a settled run alongside an unsettled alternative. Arabic strategy names explain their allocation rule; nominal-interest labels must not suggest support for flat-profit financing.

## Tests and acceptance

Add JVM tests for ranking ties, exact near-equal large money, cross-currency suppression, unsettled/missing payoff dates, cash headline eligibility, exact known-path prefix, Arabic/English resource parity and placeholder parity. Retain every prior test identity. Run the real Plan suite and both explicitly unseeded debug builds; validate compiled identities, permissions, signatures and assets. Bind results to the final exact source hashes and distinguish fresh tests from cache validation.

Native screenshot review, real form entry, schedule/path callbacks, navigation, all capability rows, current-phone/actual-data testing, backup-v4 activation and publication remain separate open gates. A compiled renderer without a reachable scenario form is not a finished user flow.
