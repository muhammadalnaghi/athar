# WM028 — native experience acceptance

## Outcome and authority

Complete the remaining Athar workflows as a calm Arabic-first native financial manager, not a collection of calculators or review chores. The user explicitly requires Impeccable for UI/UX and UX Araby for Arabic microcopy. Apply both to the rendered application and complete journeys, not merely source audits or a new design document. Preserve the Master Brief, Thmanyah typography, parchment/ink palette, one ember accent, exact money, Plan001 and exactly Today / Trends / Plan with Settings. This is refinement within the existing visual world, not an app-wide rebrand.

## Implementation priorities

Resolve blocked actions, misleading financial/loading state, unsafe save behavior and navigation dead ends before decoration. Each delivered workflow needs an obvious entry, meaningful inputs, useful result/evidence, cancellation/error recovery and durable save/reopen where required. Keep optional categorization secondary to financial understanding. Missing source coverage, stale balances, conditional projections and unsupported valuations must remain explicit. A unit pass or an ended agent run does not establish product completion.

## Arabic writing contract

Use UX Araby's purposeful, concise, natural and clear فصحى مبسطة, with Athar's established executive-warm restraint. Preserve the product's masdar action-label convention, stable financial terminology, numeral choices and literal currency. Use specific actions and recoverable errors; remove bureaucratic filler, routine تم + مصدر, قم بـ, gratuitous بنجاح, blame, emoji and exclamation marks. Never soften a financial limitation into an unsupported promise. Preserve every technical placeholder, identifier, value and plural category. Keep income, refunds, actual payments, expected obligations and optional categories semantically distinct. Do not mechanically replace bank-message fixtures or financial evidence while editing UI copy.

## Rendered acceptance

Controller walks all three destinations, every Plan workflow and relevant Settings/import/restore paths on the owned emulator, including keyboard-open completion, Back/tab restoration, loading/empty/error/long-content states, large and three-decimal money, Arabic/English and narrow/scaled text. Inspect actual screenshots for full sign/digits/currency, hierarchy, contrast, spacing, touch targets and clear next actions. Use one batched finding/fix pass and at most one confirmation pass per delivered surface; preserve unresolved failures rather than repeatedly counting test totals. No best-app, zero-bugs, real-phone or all22-capability claim from partial evidence.
